# Masterclass 05: RAG Evaluation & Metrics (The RAG Triad)

## 1. How to Evaluate RAG: The RAG Triad

Interview Question: **"How do you evaluate whether a RAG system is actually performing well? What metrics do you track?"**

The modern standard for evaluating RAG pipelines is the **RAG Triad** (popularized by RAGAS and TruLens):

```
                     ┌───────────────┐
                     │  User Query   │
                     └───────┬───────┘
                             │
            ┌────────────────┴────────────────┐
            │                                 │
   Context Relevance                  Answer Relevance
            │                                 │
            ▼                                 ▼
   ┌─────────────────┐  Faithfulness  ┌─────────────────┐
   │ Retrieved Chunks│───────────────►│Generated Answer │
   └─────────────────┘ (Groundedness) └─────────────────┘
```

### The 3 Core Metrics Defined:

#### 1. Context Relevance (Retrieval Precision)
- **Question**: *Did the retriever fetch only the relevant passages, or is it cluttered with irrelevant noise?*
- **Computation**:
  $$\text{Context Relevance} = \frac{|\text{Relevant Sentences in Retrieved Chunks}|}{|\text{Total Sentences in Retrieved Chunks}|}$$
- **Why it matters**: Irrelevant sentences saturate the context window and trigger attention distraction.

#### 2. Faithfulness / Groundedness (Anti-Hallucination)
- **Question**: *Can every claim in the generated answer be traced back to the retrieved context?*
- **Computation**:
  $$\text{Faithfulness} = \frac{|\text{Claims in Answer Grounded in Context}|}{|\text{Total Claims in Answer}|}$$
- **Score Range**: $1.0$ = 100% grounded (zero hallucination); $0.0$ = pure fabrication.

#### 3. Answer Relevance (Quality of Response)
- **Question**: *Does the generated response directly answer the user's specific prompt without evading or drifting off-topic?*
- **Computation**: High semantic similarity between the user's question embedding and generated reverse question embeddings.

## 3. LLM-as-a-Judge: Biases & Mitigations

When using an LLM to evaluate another LLM's responses, you must be prepared to discuss **evaluator biases**:

1. **Position Bias**: The evaluator prefers options listed first in pairwise comparisons.
   - *Mitigation*: Shuffle candidate order and average the evaluation scores across both orientations.
2. **Verbosity Bias**: LLMs naturally score longer, more verbose answers higher even if they contain fluff.
   - *Mitigation*: Instruct the evaluation prompt to penalize non-factual padding and focus purely on verified claim counts.
3. **Self-Enhancement Bias**: GPT-4 favors answers generated by GPT-4 over Claude or LLaMA.
   - *Mitigation*: Strip metadata identifying model origin and use distinct evaluator model families.
