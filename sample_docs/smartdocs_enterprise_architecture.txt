# SMARTDOCS AI: ENTERPRISE ARCHITECTURE AND TECHNICAL MANUAL
Document Reference: ARCH-2026-V4
Classification: Internal Engineering Guide

## 1. EXECUTIVE SUMMARY & SYSTEM OVERVIEW
SmartDocs AI is an enterprise document intelligence and Retrieval-Augmented Generation (RAG) platform. The platform ingests complex PDFs, technical manuals, and corporate policies, extracting high-dimensional semantic vector embeddings and indexing them into a relational PostgreSQL database with the pgvector extension. By combining dense semantic search with sparse lexical search via Reciprocal Rank Fusion (RRF), SmartDocs achieves high retrieval recall and minimizes large language model (LLM) hallucinations.

## 2. INGESTION AND PARSING SUBSYSTEM
The ingestion pipeline handles heterogeneous document formats including PDF, Plain Text, and Markdown.
2.1 PDF Parsing:
Documents are parsed page-by-page preserving page coordinates, character offsets, and structural hierarchy. The parser strips non-printable control characters, normalizes surrogate pairs, and consolidates excessive whitespace.
2.2 Chunking Strategy:
We implement a Recursive Character Text Splitter with a target chunk size of 500 characters and an overlap window of 80 characters (~15-20 tokens). The recursive separator hierarchy prioritizes paragraph breaks ("\n\n"), followed by line breaks ("\n"), sentence boundaries (". ", "? ", "! "), clause delimiters ("; ", ", "), and finally word boundaries (" "). This prevents truncated sentences or split numerical figures.
2.3 Overlap Justification:
The 80-character overlap prevents boundary context loss, ensuring that semantic propositions spanning two adjacent chunks remain interpretable in vector space.

## 3. EMBEDDING GENERATION AND VECTOR SPACE GEOMETRY
3.1 Vector Dimensions:
Embeddings are generated using the OpenAI text-embedding-3-small model, yielding 1536-dimensional dense vectors.
3.2 Metric Normalization:
All chunk vectors are L2-normalized upon creation: ||v||_2 = 1. Consequently, cosine distance simplifies directly to dot product calculations, significantly accelerating vector search operations on CPU and GPU hardware.
3.3 Storage Schema:
Vector columns are stored in the PostgreSQL document_chunks table using the native vector(1536) data type provided by pgvector.

## 4. VECTOR DATABASE AND INDEXING INTERNALS
4.1 pgvector vs Dedicated Vector Databases:
SmartDocs utilizes PostgreSQL with pgvector rather than standalone vector stores (e.g. Pinecone, Milvus) for three primary reasons:
1. ACID Transactional Integrity: Document records, user authentication, conversation logs, and vector embeddings share the same database transaction boundary, preventing synchronization drift.
2. Single Query Hybrid Filtering: Structured relational filters (e.g., WHERE document_id = 'xyz' AND tenant_id = 12) execute alongside vector similarity searches without two-phase cross-network joins.
3. Lower Total Cost of Ownership: Relies on mature PostgreSQL hosting infrastructure rather than expensive specialized vendor subscriptions.
4.2 Indexing Algorithm (HNSW vs IVFFlat):
We configure HNSW (Hierarchical Navigable Small World) indexing on the embedding column. HNSW constructs a multi-layer graph where lower layers contain fine-grained neighbor connections and upper layers enable logarithmic long-distance traversal. Compared to IVFFlat, HNSW delivers over 98% recall without requiring training phases or periodic re-clustering as new documents are ingested.

## 5. RETRIEVAL TUNING AND ACCURACY OPTIMIZATION
5.1 Hybrid Search via Reciprocal Rank Fusion (RRF):
To overcome semantic blind spots (e.g., rare technical codes, alphanumeric product keys, and legal clauses), SmartDocs merges dense vector cosine similarity with PostgreSQL tsvector full-text search. The fusion formula is:
RRF_Score(d) = sum(1 / (k + rank_i(d))), where k = 60.
RRF normalizes disparate score distributions into stable ordinal rankings, boosting acronym recall from 58.1% to 93.4%.
5.2 Maximal Marginal Relevance (MMR):
To prevent feeding duplicate or near-identical chunks into the LLM context, MMR re-ranks the top candidate pool using:
MMR = argmax_{d in C \ S} [ lambda * Sim(d, Q) - (1 - lambda) * max_{s in S} Sim(d, s) ]
We set lambda = 0.7, balancing high query relevance against chunk diversity.
5.3 Similarity Threshold Gating:
A strict cosine similarity cutoff (0.40) discards low-confidence chunks, preventing context contamination and reducing hallucinations by 23.3%.

## 6. CONTEXT-AWARE CONVERSATION MEMORY & PROMPT ENGINEERING
6.1 Multi-Turn Coreference Resolution:
When a user asks follow-up questions referencing earlier context (e.g., "What are its exceptions?"), a query reformulation prompt synthesizes the chat history into an independent search query before issuing database calls.
6.2 Anti-Hallucination Guardrails:
The system prompt strictly commands the LLM to ground answers exclusively within the retrieved context and output inline bracketed citations [Doc: filename, Page: X]. If retrieved evidence is insufficient, the system explicitly reports that information is missing.
